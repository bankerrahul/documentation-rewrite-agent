# Screenshot runbook (MCP-driven)

**Running the doc agent without an OpenAI key:** Use a local model via [Ollama](https://ollama.com). Install Ollama, run `ollama pull llama3.2` (or another model), then run `python run_agent.py inputs/source_feature.md`. The agent uses `OLLAMA_BASE_URL` (default `http://localhost:11434/v1`) and `OLLAMA_MODEL` (default `llama3.2`) when `OPENAI_API_KEY` is not set.

Use this runbook when `image_mapping.md` has been generated by the doc agent and you want to capture screenshots using the Cursor browser MCP (cursor-browser-extension).

## Prerequisites

- Cursor with the **cursor-browser-extension** MCP enabled.
- A running **WordPress** instance (staging or local) with the relevant Thrive product (e.g. Thrive Apprentice) installed.
- You are able to log in as admin and reach the screens described in `image_mapping.md`.

## Steps

1. **Run the doc agent** (if not already done):
   ```bash
   python run_agent.py inputs/source_feature.md
   ```
   This produces `image_mapping.md` (and `rewritten_doc.md`, `review.md`) in the same directory as the source file.

2. **Open the browser via MCP** on your staging or local WordPress URL (e.g. `https://staging.example.com/wp-admin`). Log in as admin if required.

3. **For each row in `image_mapping.md`:**
   - **Image ID** (e.g. `generate-course-selection`) is the filename to use (without extension).
   - **Description** tells you what screen to capture (e.g. "Add Course screen showing the Generate with AI option").
   - Navigate to the correct screen (menus, clicks) until the UI matches the description.
   - Call the MCP tool **`browser_take_screenshot`** with:
     - `filename`: `{image_id}.png` (e.g. `generate-course-selection.png`)
     - Optionally `element` (description of element) or `ref` (CSS selector) for element-only capture.
     - Optionally `fullPage: true` for full-page screenshots.
   - Repeat for the next row.

4. **Move screenshots into the docs asset folder:**
   - Screenshots are saved by the MCP to its configured location (often workspace or Downloads). Copy them into your chosen asset folder, for example:
     - `thrive-themes/docs/features/assets/` (per-doc), or
     - `knowledge_base/assets/`
   - Ensure filenames match the Image IDs from `image_mapping.md` (e.g. `generate-course-selection.png`).

5. **Reference images in the doc:** Use markdown image syntax with the chosen path, e.g.:
   ```markdown
   ![Thrive Apprentice Add Course screen with Generate with AI option selected](assets/generate-course-selection.png)
   ```
   Alt text can be taken from the **Alt Text** column in `image_mapping.md`.

## Quick reference: image_mapping.md columns

| Column     | Use |
|-----------|-----|
| Image ID  | Filename for screenshot (e.g. `generate-course-selection.png`) |
| Description | What to show on screen; navigate until the UI matches this. |
| Alt Text  | Use as the `alt` in `![alt](path)` for accessibility and SEO. |

## Optional: headless automation

For repeatable runs without a live Cursor session, use the Playwright screenshot runner and a machine-readable spec.

- **Runner:** `python scripts/screenshot_runner.py screenshot_spec.json --output assets` (or `-o docs/features/assets`). Set `WP_URL`, `WP_USERNAME`, and `WP_PASSWORD` in `.env` or the environment.
- **Spec:** The doc agent outputs `screenshot_spec.json` alongside `image_mapping.md` and `rewritten_doc.md` when you run `run_agent.py`. You can edit the generated spec (URLs, selectors) and run the runner against your staging base URL.
- **Schema:** See `docs/screenshot_spec_schema.md`. Example spec: `screenshot_spec.example.json`.
